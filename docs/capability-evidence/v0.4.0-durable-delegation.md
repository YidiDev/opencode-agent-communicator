# v0.4.0 durable delegation evidence

This record describes the implemented and deterministically tested release surface. It does not
represent the packed live harness as passing until `bun run test:live` is run successfully against a
supported OpenCode host.

The release adds immediate-return `session_request_send` and `session_request_start` workflows.
The first persists an ask or wait and queues one canonical work-and-request envelope to an existing
visible root. The second authorizes the request and complete start arguments, atomically persists a
start reservation and linked initial request, and admits one canonical initial envelope to a new
managed root. Callers recover terminal content through `session_request_list` and
`session_request_get`, then erase retained content with `session_request_ack`.

Deterministic unit, integration, and packed black-box coverage verifies exact source-scoped
idempotency, changed-argument conflicts, fenced atomic rollback, request deadlines and scheduler
wakeups, bounded combined envelopes, queue-only recovery, claim-before-create restart recovery,
definitive start/request reconciliation, and fail-closed ambiguous admission. Persisted delivery mode
is authoritative: queue work never falls back to steer, and stale submitting initial admission is not
replayed. Existing blocking ask/wait behavior remains covered by the same deterministic suite.

On 2026-08-28, `bun test test/unit test/integration test/black-box` completed with 1,619 passing,
8 skipped, and 0 failing tests across 198 files. This count records that run only. The packed live
harness contains dedicated send/start journeys and registration assertions. On the same date,
`bun run test:live` completed those packed journeys with 6 passing tests, 0 failures, and 319
assertions across four files. This records the run's asserted scope, not proof of unasserted races or
peer compliance.

Schema v14 records the complete-public-argument idempotency digest, request delivery mode, and linked
start operation. Exact replay returns the original durable operation and request; changing work or
request arguments conflicts. Native admission ambiguity remains explicit durable state and is never
reported as proof that a peer executed, understood, or completed the delegated work.
