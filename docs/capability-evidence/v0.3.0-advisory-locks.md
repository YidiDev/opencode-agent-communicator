# v0.3.0 advisory-lock release evidence

This document supplements, rather than rewrites, the historical OpenCode 1.18.21 capability record.
Release `0.3.0` retains the supported stable `>=1.18.21 <1.19.0` host range and builds against
OpenCode 1.18.25.

The ordinary unit and integration suites cover strict lock schemas, UTF-8 byte and TTL limits,
workspace quota, holder-only renew/release, opaque pagination, expiry cleanup, ownership fencing,
canonical ISO output, scheduler lifecycle, and best-effort active-session notification boundaries.
The packed black-box test proves that the published archive imports with the exact ordered 18-tool
manifest and contains exactly three discoverable skill files.

The packed production live harness now includes a publish/list/renew/release lock journey through an
unmodified OpenCode host and checks registration of all 18 tools and the three skills. This is the
implemented live acceptance surface, not evidence of every lock race, quota, expiry, or notification
branch. A release verification claim requires an actual successful `bun run test:live` execution;
the committed harness alone is not represented as a passing run.

On 2026-08-28, the v0.3 release-surface tree completed that command with 6 passing tests, 0
failures, and 308 assertions, including the packed lock journey. This records the run's scope, not
broader live coverage than the committed assertions.

Locks remain advisory. Neither the harness nor the implementation claims write enforcement,
authorization, guaranteed notification delivery, or peer compliance. `session_lock_list` is the
authoritative current state.
